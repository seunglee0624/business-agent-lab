Excalidraw는 어떻게 "손으로 그린 것 같은" 그림을 만들까?

분석일 2026-11-05 · 도구: REA 6.8.0 + 코드 직접 읽기 · 대상: @excalidraw/excalidraw 0.18.1 (공식 npm 배포본)

한 줄 요약. Excalidraw는 그림을 직접 삐뚤게 그리지 않습니다. "일부러 조금씩 흔들어 그리는" 전문 도구 두 개에 맡기고, 도형마다 씨앗 번호를 붙여서 몇 번을 다시 그려도 똑같이 삐뚤게 나오도록 합니다.

표시 읽는 법

확인됨 배포된 코드에서 직접 본 내용
배경지식 이번 분석에서 본 건 아니고, 해당 도구가 원래 그렇게 동작한다고 알려진 내용
추정 코드를 보고 이유나 의도를 짐작한 내용
모름 이번 분석으로는 확인할 수 없었던 내용

1. 전체 흐름 한눈에 보기

확인됨 Excalidraw 코드 안에서 roughjs(도형을 손그림처럼 흔들어 그리는 도구)와 perfect-freehand(펜 궤적을 붓 자국처럼 만드는 도구)를 불러다 씁니다. 버전은 각각 4.6.4, 1.2.0입니다.

비유하면 Excalidraw는 지휘자예요. "이 사각형은 이만큼 굵게, 이만큼 엉성하게"라고 지시만 하고, 실제로 삐뚤빼뚤한 선을 만드는 건 두 도구가 합니다.

2. 비결 ① 씨앗 번호: 매번 똑같이 삐뚤게

손그림 느낌을 내려면 선을 "무작위로" 조금씩 흔들어야 합니다. 그런데 화면은 확대, 이동, 다른 도형 선택 등으로 1초에도 여러 번 다시 그려져요. 그때마다 새로 흔들면 그림이 덜덜 떨려 보입니다.

해결책은 씨앗 번호입니다. 같은 씨앗 번호를 넣으면 무작위 결과가 항상 똑같이 나와요. 복권 추첨기에 같은 시작 번호를 넣으면 같은 번호가 나오는 것과 비슷합니다.

  • 확인됨 각 도형은 자기 씨앗 번호(seed)를 가지고 있고, 그리기 설정을 만들 때 이 번호를 roughjs에 넘깁니다.
  • 확인됨 씨앗 번호는 "현재 시각"을 출발점으로 한 난수 생성기에서 뽑습니다(0 ~ 약 21억 사이 정수).
  • 확인됨 사용자가 "엉성함" 단계를 바꾸면 그 도형의 씨앗 번호도 새로 뽑습니다. 그래서 단계를 바꾸면 흔들림 모양이 새로 정해집니다.
  • 배경지식 roughjs는 같은 씨앗을 받으면 같은 모양을 만들어 냅니다(roughjs의 공개된 동작 방식).
  • 추정 도형을 처음 만들 때 씨앗을 뽑는다고 봅니다. 씨앗 생성 코드가 "새 도형 만들기" 코드 바로 옆에 있지만, 둘이 연결되는 줄까지 직접 확인하진 않았습니다.
  • 추정 씨앗을 쓰는 목적은 "떨림 방지"라고 봅니다. 코드에 이유가 적혀 있진 않지만 이 방식의 일반적인 목적입니다.

3. 비결 ② 엉성함 3단계

  • 확인됨 엉성함은 세 단계입니다. 코드 안 이름도 architect:0, artist:1, cartoonist:2(건축가·아티스트·만화가)입니다.
  • 확인됨 엉성함이 2(만화가)보다 낮을 때는 preserveVertices 옵션을 켭니다.
  • 배경지식 이 옵션은 roughjs에서 "꼭짓점(모서리 점) 위치는 흔들지 말라"는 뜻입니다. 그래서 0·1단계에선 모서리가 제자리에 붙어 있고, 2단계에서만 모서리까지 흔들립니다.

선 스타일에 따른 세부 설정

  • 확인됨 빗금(채우기 줄) 간격 = 선 굵기 × 4, 빗금 굵기 = 선 굵기 ÷ 2
  • 확인됨 점선·파선일 때는 선을 두 번 겹쳐 그리는 효과를 끄고, 대신 선을 0.5 더 굵게 합니다.
  • 확인됨 파선은 "8 그리고 8+굵기" 간격, 점선은 "1.5 그리고 6+굵기" 간격으로 끊습니다.
  • 추정 점선에서 겹쳐 그리기를 끄는 이유는 끊어진 조각이 두 번 겹치면 지저분해 보이기 때문으로 보입니다.

4. 비결 ③ 작은 도형은 덜 흔든다

작은 상자를 크게 흔들면 상자인지 낙서인지 알아볼 수 없어요. 그래서 Excalidraw는 도형이 작으면 흔들림을 자동으로 줄입니다.

  • 확인됨 그대로 두는 경우: 짧은 변이 20 이상이면서 긴 변이 50 이상일 때. 또는 모서리가 둥근 특정 도형이 짧은 변 15 이상일 때. 또는 특정 종류의 도형이 긴 변 50 이상일 때.
  • 확인됨 줄이는 경우: 위에 해당하지 않으면 엉성함을 2로 나눕니다. 긴 변이 10 미만이면 3으로 나눕니다. 결과는 최대 2.5로 제한합니다.
  • 모름 "특정 도형", "특정 종류"가 정확히 무엇인지는 모릅니다. 배포 코드는 이름이 압축되어 있어(Ta, ae 같은 한두 글자) 확인하지 못했습니다. 화살표·선 종류일 가능성이 있습니다 추정.
  • 모름 "최대 2.5" 제한은 지금의 3단계(최대 2)에서는 실제로 걸릴 일이 없어 보입니다. 왜 들어 있는지는 알 수 없습니다.

5. 비결 ④ 한 번 계산한 모양은 보관해 둔다

  • 확인됨 도형별로 계산 결과를 보관함(WeakMap, 도형이 지워지면 자동으로 비워지는 보관함)에 저장하고, 있으면 꺼내 씁니다.
  • 확인됨 내보내기(export) 중일 때는 보관함을 쓰지 않고 새로 계산합니다.
  • 추정 내보낼 때 새로 계산하는 이유는 화면과 파일의 배경색 등 조건이 다를 수 있기 때문으로 보입니다(계산 함수에 배경색 정보가 함께 넘어감).
  • 모름 도형을 고치면 보관함에서 언제 지우는지(갱신 시점)는 이번에 확인하지 않았습니다.

6. 펜으로 그린 선은 다른 방식

  • 확인됨 펜 선은 roughjs가 아니라 perfect-freehand로 만듭니다. 그은 점들을 넘기면 "붓 자국 모양의 테두리"가 나오고, 그 안을 선 색으로 칠합니다.
  • 확인됨 설정값: 붓 크기 = 선 굵기 × 4.25, 가늘어짐 0.6, 부드럽게 0.5, 따라붙기 0.5. 펜 압력 정보가 없으면 "압력 흉내 내기" 옵션을 씁니다.
  • 모름 펜 선을 그릴 때 roughjs 모양도 함께 그리는 코드가 있는데(있을 때만), 무엇을 위한 건지(배경 채우기 등) 확인하지 못했습니다.

7. 이번 분석에서 확실하지 않은 것 (한곳에 모음)

  • 모름 실제 사이트와의 차이. 분석한 건 npm 배포본 0.18.1입니다. 지금 excalidraw.com에서 돌아가는 코드는 더 새것일 수 있습니다.
  • 모름 실행해 보지 않음. 코드를 읽기만 했고(정적 분석), 실제로 그려 보며 확인하진 않았습니다. 브라우저 방식 분석은 컴퓨터에 필요한 부품(libnspr4)이 없어 하지 못했습니다.
  • 모름 REA의 몫이 작음. REA는 코드 구조(파일 3개, 연결 관계)를 정리했지만, "손그림" 관련 단어로 경로를 추적하자 일치 항목이 없었습니다. 위 결론 대부분은 제가 코드 원문을 직접 찾아 읽은 결과입니다.
  • 모름 압축된 이름. 배포 코드는 함수 이름이 한두 글자로 줄어 있어서, 일부 조건(4장)의 정확한 의미를 알 수 없었습니다.
  • 추정 문서 안의 "왜 그렇게 했는지" 설명은 모두 추정입니다. 코드는 "무엇을 하는지"만 보여주고 "왜"는 알려주지 않습니다.
  • 그림(도식) 속 삐뚤어진 사각형은 이해를 돕기 위해 손으로 만든 예시이고, Excalidraw가 실제로 출력한 그림이 아닙니다.

용어 풀이

  • REA: 소스 코드 없이 완성된 프로그램을 들여다보는 분석 도구.
  • 번들: 웹사이트가 쓰는 코드를 몇 개의 큰 파일로 합치고 압축한 것. 사람이 읽기 어렵게 이름이 줄어 있음.
  • 정적 분석: 프로그램을 실행하지 않고 코드만 읽어서 분석하는 방법.
  • 씨앗(seed): 무작위 결과의 출발점이 되는 숫자. 같은 씨앗이면 같은 "무작위" 결과가 나옴.
  • 캐시: 한 번 계산한 결과를 보관해 두고 다시 쓰는 것.
  • canvas: 웹페이지 안의 그림판 영역.
